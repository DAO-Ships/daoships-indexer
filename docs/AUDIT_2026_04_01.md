# Indexer Audit Report — 2026-04-01

Full codebase audit after INavigator integration, ragequit total_shares fix, navigator.metadata removal, and navigator.allowlist addition.

---

## HIGH

### H1. Reorg cleanup misses total_shares / total_loot recalculation — FIXED

**File:** `supabase/migrations/schema.sql` (ds_delete_events_after_block)

`ds_delete_events_after_block` recalculates `proposal_count` and `active_member_count` from surviving rows, but `total_shares` and `total_loot` are delta-accumulated (handleMintOrBurn, handleRagequit) and never recomputed. After a reorg, the deltas replay against stale totals, causing double-counting.

**Fix applied:** Added `total_shares` and `total_loot` recalculation via `COALESCE(SUM(m.shares/m.loot), 0)` from `ds_members` to the UPDATE in `ds_delete_events_after_block`.

---

## MEDIUM

### M1. Transfer topic0 over-fetching in fetchAllLogs — FIXED

**File:** `src/services/processor.ts`

`fetchAllLogs` used topic0 OR-filter with no address filter. Transfer's topic0 (`0xddf252ad...`) matches every ERC20/ERC721 transfer on the chain. The RPC returned all matching logs, then the indexer filtered in-memory to known addresses.

**Fix applied:** `fetchAllLogs` now passes `knownAddresses` as the server-side address filter to `getLogs`. In-memory filtering removed. Comment notes batching needed if address list exceeds RPC limits (~50-100).

### M2. Reorg recovery doesn't clean ContractRegistry — FIXED

**File:** `src/registry/contract-registry.ts`, `src/index.ts`

After reorg cleanup, the SQL deletes orphaned navigators/DAOs but the in-memory `ContractRegistry` retained stale entries.

**Fix applied:** Added `clear()` method to `ContractRegistry`. Reorg handler in `index.ts` now calls `registry.clear()` then rebuilds from surviving DB rows via `getAllDaosIterator` and `getActiveNavigatorsIterator`.

### M3. Member upsert on Transfer missing updated_at — FIXED

**File:** `src/handlers/tokens.ts`

The `upsertMember` calls in the Transfer handler didn't include `updated_at`. PostgreSQL's `DEFAULT NOW()` only applies on INSERT, not on the UPDATE branch of an upsert.

**Fix applied:** Added `updated_at: now` to both sender and receiver upsert payloads in `handleTransfer`.

# Second Audit — 2026-04-07

Full codebase re-audit after pre-DAO allowlist feature (nullable dao_id, on-chain verification, reparenting, pruning). All first-audit fixes verified intact with no regressions.

## CRITICAL

### C1. verifyAllowlistOnChain ABI result length check too loose — FIXED

**File:** `src/handlers/poster.ts`

Length check used `< 66` (lower bound only). A longer-than-expected RPC return could pass validation with wrong bytes extracted. Also, `allowlistRoot()` parsing used `padStart` unnecessarily.

**Fix applied:** Changed to strict `!== 66` length check for both `daoShip()` and `allowlistRoot()` results. Removed `padStart`. Added try/catch around each `rawCall` to catch revert/timeout as deterministic (return false) rather than letting them propagate as transient.

## HIGH

### H1. rawCall timeout creates infinite retry loop — FIXED

**File:** `src/handlers/poster.ts`

A navigator contract that consistently times out (>10s) on `daoShip()` or `allowlistRoot()` would throw, which the processor classified as transient, retrying the block range forever.

**Fix applied:** Wrapped both `rawCall` calls in try/catch within `verifyAllowlistOnChain`. Timeout/revert errors are deterministic for a given contract — return false (drop post). Only `getCode` errors propagate (transient network-level).

### H2. Catch-all swallows transient DB errors in allowlist path — FIXED

**File:** `src/handlers/poster.ts`

Bare `catch {}` around `getDao()` in the allowlist branch silently fell through to on-chain verification on transient Supabase errors. Records that should use MEMBER trust got stored as ON_CHAIN_PROVISIONAL.

**Fix applied:** Removed the try/catch. DB errors now propagate to the processor for block range retry.

## MEDIUM

### M1. Double validation in allowlist path — FIXED

**File:** `src/handlers/poster.ts`

`validateNavigatorAllowlist` ran twice — once for address/root extraction, again in the generic block.

**Fix applied:** Hoisted `preValidated` to outer scope. Generic validation block skipped when `isNavigatorAllowlist && preValidated`.

### M2. Reparenting doesn't update trust_level — FIXED

**File:** `supabase/migrations/schema.sql`

Reparented records kept `ON_CHAIN_PROVISIONAL` permanently.

**Fix applied:** `ds_reparent_orphaned_records` now sets `trust_level = 'MEMBER'` alongside `dao_id`.

### M3. Reparenting race — attacker front-runs DAO launch — FIXED

**Files:** `src/handlers/launcher.ts`, `src/handlers/daoship.ts`, `supabase/migrations/schema.sql`, `src/services/database.ts`

Reparenting in the launcher happened before any navigator was registered, allowing crafted records to be adopted. The SQL function matched on `daoAddress` only, not `navigatorAddress`.

**Fix applied:**
1. Moved reparenting from launcher handlers to `handleNavigatorSet` (fires when governance registers the navigator)
2. Added `p_navigator_address` parameter to `ds_reparent_orphaned_records` SQL function
3. WHERE clause now matches both `daoAddress` AND `navigatorAddress` in content_json
4. Only reparents when `permission > 0` (navigator being activated)

### M4. fetchAllLogs has no address batching — FIXED

**File:** `src/services/processor.ts`

All known addresses sent in a single `getLogs` call with no chunking.

**Fix applied:** Added batching using existing `GET_LOGS_ADDRESS_CHUNK_SIZE` (100). Single call for <=100 addresses, chunked loop for more.

### M5. lastPruneTime initialized to 0 triggers prune on first poll — FIXED

**File:** `src/index.ts`

**Fix applied:** Changed `let lastPruneTime = 0` to `let lastPruneTime = Date.now()`.

# Third Audit — 2026-04-09

Full codebase re-audit after contracts hardening alignment (deployer/launcher_contract separation, ipfsCid validation, navigator updated_at/config, reparent trust preservation). All 30 prior fixes verified intact.

## HIGH

### H1. Navigator deactivation overwrites metadata with null — FIXED

**File:** `src/handlers/daoship.ts:511-568`

When `permission === 0` (navigator deactivation), the NavigatorDeployed fetch is skipped (line 516: `if (permission > 0)`), leaving `deployerAddress`, `navigatorType`, `navName`, `navDescription` as `null`. The upsert at line 554 then writes these null values over the existing row, permanently erasing the navigator's historical metadata (deployer, name, description, type).

**Impact:** Deactivated navigators lose all metadata. If later reactivated, metadata must be re-fetched.

**Fix:** When `permission === 0`, use a targeted update instead of a full upsert. Only update `permission`, `permission_label`, `is_active`, `updated_at`, and `tx_hash`. Preserve existing deployer/name/description/type.

### H2. Reparent SQL case-sensitive address matching — FIXED

**File:** `src/handlers/poster.ts:291-296` + `supabase/migrations/schema.sql:573-575`

`validateNavigatorAllowlist` uses `str(p.daoAddress, 42)` which does NOT lowercase. `ETH_ADDRESS_RE` accepts mixed case (`/^0x[0-9a-fA-F]{40}$/`). So `content_json` may store `"0xABC..."` while the reparent SQL parameter `p_dao_address` is lowercased via `validateAndNormalizeAddress`. The `WHERE content_json->>'daoAddress' = p_dao_address` comparison fails due to case mismatch.

**Impact:** Orphaned allowlist records are never reparented when the DAO launches.

**Fix:** Lowercase `daoAddress` and `navigatorAddress` in `validateNavigatorAllowlist` before returning them in the validated object.

## MEDIUM

### M1. Reorg cleanup does not roll back member balances — FIXED

**File:** `supabase/migrations/schema.sql:494-540`

`ds_delete_events_after_block` deletes proposals, votes, records, navigators, etc. after the fork point. It recalculates `total_shares`/`total_loot` from surviving `ds_members` rows. However, member `shares`/`loot` balances themselves are NOT cleaned up. Since `handleTransfer` uses additive/subtractive deltas on existing balances, replaying Transfer events after reorg double-counts the deltas.

**Impact:** After a reorg, member balances and DAO totals are incorrect until a full re-index.

**Note:** This is a pre-existing architectural limitation. The practical mitigation is that reorgs on Quai are rare and shallow. A full fix requires either per-block balance snapshots or deleting member rows for affected DAOs during cleanup.

**Fix (practical):** Delete member rows for affected DAOs in `ds_delete_events_after_block`, then let the replay recreate them from Transfer events. Add after step 2:
```sql
DELETE FROM ds_members m WHERE m.dao_id = ANY(affected_daos);
```

### M2. CID_RE regex only matches `bafy` CIDv1 prefix — FIXED

**File:** `src/handlers/poster.ts:289`

`CID_RE = /^(Qm[1-9A-HJ-NP-Za-km-z]{44}|bafy[a-z2-7]{50,62})$/` only matches CIDv1 with `bafy` prefix (base32, dag-pb, sha2-256). Valid CIDv1 CIDs can also start with `bafk` (dag-cbor) or other prefixes.

**Impact:** Allowlist posts using dag-cbor IPFS encoding are rejected.

**Fix:** Broaden to `baf[a-z2-7]{51,63}` to cover all common CIDv1 variants.

## LOW

### L1. Non-allowlist getDao catch swallows transient DB errors — FIXED

**File:** `src/handlers/poster.ts:486-494`

For non-allowlist tags, `getDao` is wrapped in a try/catch that logs at `debug` level and continues. Transient Supabase errors (timeouts, connection drops) cause the post to be permanently dropped rather than retried via the processor's block range retry mechanism.

**Fix:** Remove the try/catch. Let DB errors propagate, matching the allowlist path behavior (H2 fix from second audit).

### L2. Reparent preserves ON_CHAIN_PROVISIONAL instead of upgrading — FIXED

**File:** `supabase/migrations/schema.sql:567-570`

The CASE statement preserves `ON_CHAIN_PROVISIONAL` unchanged during reparenting. Since reparenting means the DAO now exists and the navigator is registered, the trust should upgrade to `MEMBER`.

**Fix:** Remove `ON_CHAIN_PROVISIONAL` from the preservation list:
```sql
WHEN trust_level IN ('SEMI_TRUSTED', 'VERIFIED_INITIAL', 'VERIFIED') THEN trust_level
```

### L3. handleDelegateChanged missing updated_at — FIXED

**File:** `src/handlers/tokens.ts:148-155`

`upsertMember` call does not include `updated_at`. PostgreSQL `DEFAULT NOW()` only applies on INSERT; on UPDATE the existing value is preserved. Same class of bug as the first audit's M3 (Transfer handler missing updated_at).

**Fix:** Add `updated_at: now` to the upsert.

### L4. handleDelegateVotesChanged missing updated_at — FIXED

**File:** `src/handlers/tokens.ts:185-192`

Same issue as L3.

**Fix:** Add `updated_at: now` to the upsert.

### L5. Discovery pass fetchLogsForAddresses no topic filter — FIXED

**File:** `src/services/processor.ts:235`

`getLogs(batch, fromBlock, toBlock)` is called without a topics parameter, fetching ALL logs from discovered addresses instead of filtering by registered topic0 hashes. Wastes bandwidth but no correctness impact — the dispatcher ignores unrecognized topics.

**Fix:** Pass `[registeredTopics]` to match `fetchAllLogs` behavior.

## INFO

- `allowlistRoot` extraction (`'0x' + rootResult.slice(2)`) is a redundant identity operation — cosmetic only
- `permissionToLabel` bit mask (`permission & 7`) is dead code after the 0-7 validation guard
- Orphaned `dao_id IS NULL` records visible via public RLS — acceptable (public blockchain data)
- `BLOCKED_KEYS` check in `linksObj` is correctly essential (not redundant with `KEY_PATTERN`)
- `fetchLogsForAddresses` intentionally fetches all logs for discovery (not strictly a bug)
